# GitHub 팀 설정 체크리스트

파일로 제공되는 협업 규칙과 GitHub에서 직접 적용하는 관리 설정은 별개입니다. 아래 항목은 저장소 관리자가 팀 구성과 사용 가능한 GitHub 기능에 맞춰 확인합니다. 이 문서가 추가되어도 설정이 자동 적용되지는 않습니다.

## 초기 설정

- [ ] README에 프로젝트 목표, 주요 기능, 기술 스택, 팀원 및 역할을 작성합니다.
- [ ] 첫 커밋을 원격에 올리고 기본 브랜치가 `main`인지 확인합니다.
- [ ] 저장소 설명, 공개 범위, Topics를 정합니다.
- [ ] 팀원을 초대하고 필요한 범위의 접근 권한을 부여합니다.
- [ ] 이슈 담당, 리뷰 요청, 긴급 연락에 사용할 팀 채널을 정합니다.
- [ ] 코드의 공개·재사용 정책을 합의하고 필요한 라이선스를 추가합니다.

## 브랜치와 PR

- [ ] `main`에 브랜치 보호 또는 Ruleset을 설정합니다.
- [ ] `main` 변경에 PR과 다른 팀원 1명 이상의 승인을 요구합니다.
- [ ] 병합 전 리뷰 대화 해결을 요구합니다.
- [ ] `main`의 강제 푸시와 삭제를 제한합니다.
- [ ] 팀에 맞는 병합 방식을 선택합니다. 기본 권장 방식은 Squash merge입니다.
- [ ] 병합 후 작업 브랜치 자동 삭제를 활성화합니다.
- [ ] CI를 도입한 뒤 실제로 실행되는 검사 이름을 필수 상태 검사로 지정합니다.

설정 위치와 사용 가능한 보호 기능은 저장소 유형과 요금제에 따라 다를 수 있습니다. 적용 후 일반 팀원 권한에서도 의도대로 동작하는지 확인해주세요.

## 개발 환경 확정 후

- [ ] README에 런타임 버전, 설치·실행·테스트·빌드 명령을 추가합니다.
- [ ] 필요한 환경 변수를 가짜 값으로 작성한 `.env.example`을 추가합니다.
- [ ] 기술 스택에 맞는 포매터와 린터를 설정합니다.
- [ ] 패키지 매니저를 정하고 잠금 파일을 커밋합니다.
- [ ] 실제 실행 가능한 린트·테스트·빌드 명령으로 CI를 추가합니다.
- [ ] 의존성 매니페스트가 생기면 Dependabot 등 업데이트 자동화 도입을 검토합니다.
- [ ] 담당 영역이 정해지면 실제 GitHub 계정 또는 팀으로 `CODEOWNERS`를 작성합니다.

현재는 기술 스택과 담당자가 정해지지 않아 CI, 의존성 자동 업데이트, `CODEOWNERS`, 라이선스를 추가하지 않았습니다.
